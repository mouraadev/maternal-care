# Projeto Doul.IA — Estrutura inicial do repositório

Você é um engenheiro de software sênior. Crie a estrutura completa de um repositório para o **Doul.IA**, uma plataforma de acompanhamento gestacional com inteligência artificial, desenvolvida para um hackathon da OpenAI.

O objetivo é deixar toda a arquitetura, pastas, configurações, dependências e integrações iniciais preparadas para que dois desenvolvedores trabalhem em paralelo.

## 1. Stack

- **Frontend:** React, Vite, TypeScript e Tailwind CSS.
- **Componentes:** Lucide React e Recharts.
- **Banco de dados:** Firebase Cloud Firestore.
- **Autenticação:** Firebase Authentication.
- **Backend:** Firebase Cloud Functions com TypeScript.
- **IA:** API da OpenAI, integrada pelas Cloud Functions.
- **Versionamento:** Git e GitHub.

Priorize uma arquitetura simples, modular e rápida de desenvolver.

## 2. Funcionalidades

O sistema terá três perfis com autenticação e redirecionamento automático.

**Administrador**
- Cadastro e gerenciamento de médicos e pacientes.
- Vinculação de pacientes aos médicos.
- Dashboard geral de médicos, pacientes e atendimentos.

**Médico**
- Dashboard de pacientes vinculados.
- Visualização e edição de dados de acompanhamento.
- Fila de solicitações de atendimento.
- Atualização do status dos atendimentos.

**Paciente**
- Dashboard humanizado com informações da gestação.
- Linha do tempo e previsão das etapas gestacionais.
- Histórico de consultas e atendimentos.
- Chat com assistente virtual personalizada, chamada Lia.
- Solicitação de atendimento médico.

**IA**
- Acompanhamento educativo e personalizado conforme a fase gestacional.
- Conversas acolhedoras e contextualizadas.
- Sem diagnósticos, prescrições ou substituição de orientação médica.
- Integração segura, sem expor chaves da OpenAI no frontend.

## 5. Requisitos de implementação

1. Crie efetivamente todos os diretórios e arquivos necessários, não apenas uma representação da estrutura.
2. Configure as dependências e scripts para desenvolvimento, build e testes.
3. Prepare Firebase Authentication com os perfis `admin`, `doctor` e `patient`, usando regras seguras de autorização.
4. Estruture as coleções Firestore, os serviços de acesso e as regras de segurança, impedindo acesso indevido a dados de outras pacientes.
5. Crie as rotas e layouts iniciais das três interfaces.
6. Configure a comunicação com Cloud Functions e a estrutura do assistente de IA.
7. Utilize Firebase Emulator Suite para desenvolvimento local quando aplicável.
8. Crie dados fictícios de demonstração, sem informações médicas reais.
9. Documente o propósito de cada pasta, a configuração das variáveis de ambiente e como executar o projeto.
10. Garanta que os dois desenvolvedores possam trabalhar independentemente, com interfaces e contratos de dados bem definidos.
